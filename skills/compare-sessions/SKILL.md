# Compare sessions

Порівняльний аналіз сесій Claude Code за токенами/вартістю з наративними висновками.
Аналізатор: `node /home/anikkhoma/repos/cf/claude-usage/compare.mjs` (сесії шукаються
за custom title — підрядком імені — або UUID-префіксом, по всіх проєктах `~/.claude/projects`).

## Кроки

1. **Дані.** Запусти аналізатор у JSON-режимі (одна або більше сесій):
   ```sh
   node /home/anikkhoma/repos/cf/claude-usage/compare.mjs <name1> [<name2> ...] --json > /tmp/session-compare.json
   ```
   Якщо ім'я неоднозначне — скрипт виведе список збігів у stderr; покажи його користувачу
   і попроси уточнити (або сам обери, якщо з контексту розмови очевидно, яку сесію мали на увазі,
   і скажи, яку обрав).

2. **Прочитай** `/tmp/session-compare.json` і проаналізуй. Дивись на:
   - **Вартість**: total / main / subagents по сесіях; хто дешевший і за рахунок чого.
   - **Кеш-економіку**: частка cache-read; обсяг cache write 1h (×2!) vs 5m; сесія з
     багатьма compact'ами платить повторними cache-write — це видно у `tokens.cacheWrite*`.
   - **Compact-и** (`compacts`): скільки, trigger (manual/auto), скільки токенів скинуто
     (pre→post) і чи після них зросли витрати на ходи.
   - **Ходи** (`turns`): найдорожчі ходи і чому (багато calls? сабагенти? роздутий context_end?);
     як росте `context_end` по ходах.
   - **Сабагентів** (`subagents`): чи окупились (вартість vs що зробили за description),
     середня вартість виклику, чи не дублювали роботу (схожі descriptions), % cache-read
     у сабагентів (низький = кожен платив за холодний контекст).
   - **Темп**: cost/годину активного часу, tokens per tool call — як проксі "щільності" роботи.
   - Якщо порівнюються стратегії виконання однієї задачі — сформулюй вердикт: яка стратегія
     ефективніша за $ і за часом, і в чому механізм різниці (не тільки цифри).

3. **HTML-звіт.** Згенеруй у поточну директорію:
   ```sh
   node /home/anikkhoma/repos/cf/claude-usage/compare.mjs <ті самі імена> -o ./session-compare-$(date +%Y%m%d-%H%M).html
   ```

4. **Впиши висновки у звіт** (Edit, не Write). У файлі є блок:
   ```html
   <div class="card" id="findings" hidden>
     <h3 style="margin-top:0">Висновки</h3>
     <!-- AGENT: findings -->
   </div>
   ```
   - Прибери атрибут `hidden`.
   - Заміни `<!-- AGENT: findings -->` на 3–7 однорядкових висновків, точний markup:
     ```html
     <div class="take bad"><div class="fig">82.9%</div><div class="txt"><b>28-ombr</b>: сабагенти зʼїли 82.9% вартості — 9 запусків, з них 3 переробляли одне й те саме</div></div>
     ```
     Класи: `.take bad` — марнотратство/аномалія (червона цифра), `.take good` — здоровий
     сигнал (зелена), `.take info` — нейтральний факт (синя). `.fig` — одна коротка цифра
     (%, $, множник типу `3×`), `.txt` — одне речення з назвою сесії/сабагента в `<b>`.
   - За бажанням додай 1–2 `<div class="callout">…</div>` з конкретними рекомендаціями
     ("наступного разу scope сабагента X вужче — він читав весь репозиторій заради одного файлу").

5. **Відповідь у чаті**: короткий вердикт (яка сесія/стратегія ефективніша і чому, 3–6
   пунктів з цифрами) + шлях до звіту. Не переказуй усі таблиці — вони у звіті.

## Нотатки

- Токени моделей без відомої ціни виключені з $ (JSON: `totals.unknown_model_tokens`,
  у звіті — попередження). Якщо їх багато — скажи про це явно.
- Вартість сабагента атрибутована до батьківського ходу (`turns[].cost_usd` включає їх).
- `context_end` ходу ≈ розмір контексту наприкінці ходу; різкий стрибок між ходами без
  compact — хтось влив великий файл/вивід у контекст.
- Одна сесія теж валідна — тоді без порівняння, просто розбір: де гроші, що оптимізувати.
