# claude-usage

Глибокий аналіз використання токенів/вартості конкретних сесій Claude Code —
разом із їхніми сабагентами — та порівняння кількох сесій між собою.

Призначення: порівнювати ефективність різних стратегій виконання однієї задачі
(сабагенти vs періодичний compact vs монолітна сесія тощо).

## Використання

```sh
node compare.mjs <ім'я-сесії> [<ім'я-сесії> ...] [опції]
```

Сесія вказується **іменем** (custom title, який ви даєте сесії в Claude Code) —
матчинг за підрядком, без урахування регістру. Fallback — префікс UUID сесії.
Пошук іде по всіх проєктах у `~/.claude/projects`. Якщо ім'я неоднозначне —
помилка зі списком збігів (уточніть фрагмент або дайте UUID-префікс).

Опції:

- `--json` — повний JSON у stdout замість HTML (машинний інтерфейс)
- `-o <file>` — шлях вихідного HTML (за замовчуванням `./session-compare-<stamp>.html` у cwd)
- `--dir <path>` — інша тека транскриптів (за замовчуванням `~/.claude/projects`)

Приклади:

```sh
# порівняти дві сесії
node compare.mjs 39-zrp-chbp-ground 41-ombr-16-ak-ground

# глибокий розбір однієї сесії
node compare.mjs "unitId=19ak"

# JSON для своїх скриптів
node compare.mjs my-session --json > data.json
```

## Скіл `/compare-sessions`

`skills/compare-sessions/SKILL.md` (симлінк у `~/.claude/skills/compare-sessions`) —
обгортка для Claude Code: `/compare-sessions name1 name2` запускає аналізатор,
пише наративні висновки (що краще/гірше і чому) у блок «Висновки» HTML-звіту
і дає короткий вердикт у чаті.

## Що у звіті

- **Порівняльна таблиця**: вартість у $ (головна метрика, з розкладом main/сабагенти),
  токени за 4 типами (input / cache write 5m / cache write 1h / cache read / output),
  частка cache-read, кількість викликів, ходів, сабагентів, compact'ів, час.
- **Крива контексту** (input + cache read + cache write на виклик ≈ поточний розмір
  контексту) — накладена по сесіях, вісь X = час від старту сесії. Маркери:
  ▼ compact, ○ spawn сабагента, ◆ зміна моделі.
- **Кумулятивна крива вартості** головної сесії.
- **По кожній сесії**: таблиця ходів (промпт → вартість ходу включно з породженими
  сабагентами, tool-виклики, контекст наприкінці ходу, тривалість); таблиця
  сабагентів (тип, опис, батьківський хід, токени, % cache-read, вартість);
  криві контексту топ-3 найдорожчих сабагентів; таблиця compact-подій
  (trigger, preTokens → postTokens, тривалість).

Звіт — самодостатній HTML (без CDN), світла/темна тема (`prefers-color-scheme`
+ кнопка перемикання).

## Вартість

Ціни захардкоджені в `PRICING` у `compare.mjs` (USD за MTok) і показані у звіті
(розділ "Pricing used"). Множники кешу: запис 5m ×1.25, запис 1h ×2 (розбивка
береться з `usage.cache_creation.ephemeral_1h/5m_input_tokens`), читання ×0.1
від ціни input. Токени моделей без відомої ціни рахуються, але в $ не входять —
звіт показує попередження.

## Обмеження

- Назва сесії шукається в перших 64KB транскрипта — перейменована глибоко
  в сесії назва може не знайтися (використайте UUID-префікс).
- Вартість сабагентів атрибутується до ходу, який їх породив; на кумулятивній
  кривій вартості показана лише головна сесія.
- Zero-usage записи (`<synthetic>` тощо) відфільтровано.
